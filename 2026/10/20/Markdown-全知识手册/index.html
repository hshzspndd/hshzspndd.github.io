一、Markdown 是什么

Markdown 是一种轻量级标记语言，由 John Gruber 于 2004 年发布。核心理念：

  1. 易读易写：纯文本就能表达排版，不依赖 Word 那种”所见即所得”编辑器。
  2. 可转换：一份 .md 文件可以转换成 HTML、PDF、Word、幻灯片等几乎所有格式。
  3. 生态庞大：GitHub、GitLab、语雀、飞书、知乎、掘金、Typora、Obsidian、VS Code……到处都在用它。

简单说：你用记事本写，它给你排版；你用任何编辑器写，它都能渲染。

本手册遵循 GFM（GitHub Flavored Markdown） 标准，这是目前最主流的方言，兼容性最好。

二、基本语法

1. 标题

用 # 的个数表示级别，1~6 级：

规则与坑：

  • # 后面必须有一个空格，否则可能不识别（部分方言仍识别，但不规范）。
  • 标题下加 ===（一级）或 ---（二级）是 Setext 旧式写法，现在少用。
  • 分级要连续：别从一级直接跳三级，爬楼没有跳层的。

2. 段落与换行

关键坑——换行规则（本手册最值得背的一条）：

写法 效果
段落内直接回车 渲染为空格，不换行
行尾加两个空格再回车 硬换行（<br>）
行尾加反斜杠 \ 部分方言支持，等同于硬换行
空一行 新段落

坑：

  • 表头分隔行必须有（--- 那行），否则整表不渲染。

五、常见坑与兼容性

坑 表现 解法
--- 被识别为标题 分隔线变二级标题 上方留空行
换行不生效 两行拼成一行 行尾两空格 / 空行
* 与中文粘连 斜体不生效 符号与文字间不留空格，统一用 *
表格缺分隔行 整表不渲染 检查 `
列表缩进不一致 嵌套错乱 子项缩进统一
_ 用于斜体 中文下划线冲突 用 *
代码块内三个反引号 提前结束 外层用四个反引号
中文标点后换行 部分平台断句异常 使用中文全角标点 + 规范换行
同一个文件跨平台渲染不同 表格/脚注/高亮时有时无 以 GFM 为准，少用方言特性

兼容性分级速查：

  • 全平台通用：标题、列表、链接、图片、粗斜体、引用、分隔线、代码。
  • GFM 层（GitHub/掘金/知乎等支持）：表格、任务列表、删除线、围栏代码。
  • 编辑器私有（Typora/Obsidian 等）：脚注、高亮 ==、数学公式、Mermaid、Front Matter。

原则：公开分享用 GFM 能渲染的语法；自己笔记随便用方言。

七、最佳实践

  1. 标题层级从 1 级开始且连续，一篇文档不要出现多个一级标题（除了文档标题）。
  2. 段落之间空行，段落内不硬换行，交给渲染器自动折行。
  3. 列表与文字之间空行，避免列表粘连正文。
  4. 表格不要太宽：超过 6~8 列就该考虑拆表或换思路。
  5. 图片永远写替代文字，为自己的可访问性和后期维护负责。
  6. 长文档加目录，目录用锚点实现，或依赖渲染器自动生成 TOC。
  7. 代码块永远标注语言，否则没有高亮，等于白写。
  8. 引用的引用少嵌套，超过两层基本没人看得懂。
  9. 文件名用连字符而非空格：markdown-guide.md 优于 markdown guide.md。
  10. 写给别人看的，用 GFM 子集；写给自己看的，随便用。

八、一页速查表

结语

Markdown 的全部知识，本质就是三条：

  1. 符号即语义：#、*、-、>、反引号，每个符号都对应一个排版动作。
  2. 标准有方言：先掌握通用语法，再用 GFM，最后才碰编辑器私有特性。
  3. 纯文本是王道：任何编辑器都能写，任何系统都能读，永不失效。

现在，去把这篇手册变成你自己的第一篇真正的博客文章吧——总比留在 Hello World 里强。
